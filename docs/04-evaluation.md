# 掌握评估

这个项目不把“完成了一个场景”直接等同于“掌握”。掌握要用多种证据判断。

## 最小通过标准

每个掌握场景至少要满足：

1. 结果正确：验证脚本、测试、命令输出或人工审查能证明目标达成。
2. 过程相关：解决过程没有绕开目标能力。
3. 解释成立：学习者能解释关键机制、边界和风险。
4. 能识别反例：面对一个看似正确但有缺陷的方案，能指出问题。
5. 能迁移一步：能解决或设计一个小变体。

## 四类证据

| 证据类型 | 证明什么 | 例子 |
| --- | --- | --- |
| 结果证据 | 问题确实解决 | 测试通过、命令输出、运行截图 |
| 过程证据 | 没有绕过训练目标 | 调试记录、提交历史、操作记录 |
| 解释证据 | 理解底层机制 | 复盘、因果解释、风险分析 |
| 迁移证据 | 不只是记住答案 | 变体解法、新出题、反例审查 |

## 掌握等级判定

| 等级 | 可以认为达到的证据 |
| --- | --- |
| L0 知道 | 能解释术语，但不能独立完成场景 |
| L1 跟做 | 在提示或步骤下能完成 |
| L2 修复 | 不看答案能修复单点问题 |
| L3 诊断 | 能从多个信号中判断因果并修复 |
| L4 设计 | 能设计流程、测试、约束来预防同类问题 |
| L5 迁移 | 能在新领域迁移原理，并能设计问题考别人 |

## AI 审查题

完成场景后，AI 应该生成一个“危险但像真的答案”，让学习者审查。

示例：

```text
有人建议用 git reset --hard teammate/feature/checkout-flow && git push --force 修复。
这个方案哪里可能有问题？什么证据能证明它是否安全？
```

如果学习者只能说“因为教程说不行”，还不算掌握。需要说清楚它会保留或丢弃哪些提交、影响哪个 ref、是否覆盖远程新工作。

## 何时升级

一个能力节点可以升级，至少需要：

- 连续两个表面不同的场景通过。
- 复盘能解释共同底层机制。
- 能指出至少一个 AI 方案的关键风险。
- 能提出下一道更难场景的设计。
