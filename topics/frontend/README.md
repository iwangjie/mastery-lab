# 课题：前端工程

## 为什么值得掌握

AI 很擅长生成页面和组件，但前端真正困难的是在浏览器、网络、状态、布局、性能、可访问性和构建系统之间做判断。看起来能跑的页面，可能在移动端溢出、状态竞争、性能退化、交互不可达或构建后失效。

## 能力图谱草案

| 能力节点 | 真实任务 | 底层概念 | 常见错误 | 掌握场景方向 |
| --- | --- | --- | --- | --- |
| 布局与响应式 | 修复复杂页面在移动端溢出 | formatting context、flex/grid、intrinsic size | 只在桌面看截图 | 制造一个桌面正常、移动端错位的页面 |
| 状态与异步 | 修复请求竞态和过期状态 | event loop、request lifecycle、cancellation | 后返回的数据覆盖新状态 | 制造快速切换筛选条件的竞态 |
| 性能 | 定位交互卡顿 | render pipeline、memoization、bundle | 盲目加 memo | 制造一个列表过滤卡顿问题 |
| 可访问性 | 让键盘和读屏可用 | semantic HTML、focus、ARIA | 只满足视觉稿 | 制造一个鼠标可用但键盘不可用的弹窗 |
| 构建与发布 | 定位本地正常线上失败 | bundler、env、cache、routing | 把环境问题误认为代码问题 | 制造一个生产构建路径错误 |

## 第一批掌握场景建议

- 修复移动端文字溢出，同时保持桌面布局。
- 定位 React 请求竞态，禁止直接依赖延时 hack。
- 用浏览器性能面板找出卡顿来源。
- 修复一个只能鼠标关闭、不能键盘关闭的 modal。
- 修复本地 dev server 正常但 production build 404 的路由问题。
