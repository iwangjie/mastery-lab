# 课题：反汇编与逆向

## 为什么值得掌握

逆向不是背指令表，而是在缺少源码的情况下，从二进制行为里恢复程序意图。AI 可以解释指令，但如果人看不懂调用约定、栈布局、寄存器、控制流和数据流，就无法判断解释是否可靠。

## 能力图谱草案

| 能力节点 | 真实任务 | 底层概念 | 常见错误 | 掌握场景方向 |
| --- | --- | --- | --- | --- |
| 指令和寄存器 | 追踪简单函数返回值 | ISA、寄存器、flags | 把单条指令孤立理解 | 给一个小二进制，判断输入输出 |
| 栈和调用约定 | 还原函数参数和局部变量 | stack frame、calling convention | 看错参数位置 | 给 stripped binary 还原函数签名 |
| 控制流 | 找到关键分支 | jump、branch、CFG | 被无关分支带偏 | 找出 license check 分支 |
| 动态调试 | 验证静态推断 | breakpoint、watchpoint | 只看反汇编不运行 | 用调试器证明关键变量变化 |
| Patch | 修改行为并验证 | encoding、checksums、side effects | 改坏相邻指令 | 修改判断逻辑并保持程序可运行 |

## 第一批掌握场景建议

- 给一个只输出 pass/fail 的小程序，找出正确输入。
- 给一个 stripped binary，恢复两个函数的参数含义。
- 给一个简单 crackme，要求 patch 行为并说明副作用。
- 给一个混淆控制流样例，区分真实分支和干扰分支。
